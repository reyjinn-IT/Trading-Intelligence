RISK CONTROLS

01. HARDWARE-LEVEL
Deadman Switch

A dedicated heartbeat daemon continually monitors the connection between the client UI and the engine API. It expects a ping every 30 seconds.

If the application crashes, the browser window is closed abruptly, or the network connection drops, it automatically fires failsafe routines directly to the exchange to cancel all open limit/stop orders across active pairs.

02. ZERO RISK TESTING
Paper Trading Mode

The terminal strictly boots in simulation mode by default. All API orders are executed inside a local memory state, simulating exchange latency and orderbook depth.

The LIVE_TRADING flag must be manually toggled to ensure algorithms operate identically in simulation as they will in production before risking capital.

03. DRAWDOWN CAPPING
Dynamic Invalidation

Stop losses are not calculated using arbitrary percentage drops. The terminal dynamically computes the exact point of structural invalidation based on prior swing structures and POI zones.

If the invalidation point requires risking more than the internal 2% max-drawdown threshold, the trade setup is entirely rejected regardless of confluence score.
